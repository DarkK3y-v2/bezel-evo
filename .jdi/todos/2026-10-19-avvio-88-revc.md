# Avvio personalizzato sul display 8,8 Rev C

## Esito della verifica richiesta

Distinguere due capacità:

- **Contenuto autonomo dopo il boot del SoC, prima di Bezel: confermato.**
  Il protocollo seriale ha OPTIONS start mode 1 (album immagini della SD) e
  2 (primo video della SD). Sul dispositivo ROM 1.90 queste modalità sono già
  state provate fisicamente il 3 ottobre, compreso il riavvio senza il programma.
- **Sostituzione dello specifico logo iniziale del firmware: non confermata.**
  La funzione di Libre Panel opera sul protocollo TUR_USB, non su Rev C seriale.
  Non dedurre impossibilità dalla mancanza di un comando nel driver: mancano
  riscontri sul firmware esatto del dispositivo per questa specifica capacità.

## Evidenze consultate il 19 ottobre

1. Nuova enumerazione sola lettura con CLI .55: display COM6, 0525:a4a7,
   MCU COM4, 1a86:ca88 CT88INCH. Il firmware 1.90 è l'ultimo identificato
   nelle prove già registrate, non una nuova lettura HELLO in questo turno.
2. [Protocollo locale e prove reali](../../docs/reverse-engineering/protocol-turing-rev-c.md#19-hardware-observations):
   start mode 1 scorre tutte le immagini di `/mnt/SDCARD/img/` ogni 3–5 secondi;
   start mode 2 usa il primo elemento di `/mnt/SDCARD/video/`, non l'ultimo
   file riprodotto tramite PLAY_VIDEO. Impostazione applicata al riavvio del SoC.
3. [Driver pubblico Rev C](https://github.com/mathoudebine/turing-smart-screen-python/blob/main/library/lcd/lcd_comm_rev_c.py):
   enum start mode default/image/video e OPTIONS, senza un comando boot-logo.
4. [Libre Panel](https://github.com/syntensa/libre-panel/blob/main/src/libre_panel/devices/panel_files.py):
   boot.jpg e standby.h264, con selezione modelli usb-turing. Il driver seriale
   separato non implementa questa funzione. Non confondere il nome 8,8 delle
   due generazioni hardware.
5. Inventario locale dell'app ufficiale: pulsante Boot Logo nascosto, prova
   insufficiente per affermare che sia usato dal ramo seriale. L'eseguibile
   Desktop V3.1.0 è offuscato; ispezionati metadati e stringhe senza eseguirlo.
6. [Indagine firmware precedente](../../docs/reverse-engineering/firmware-investigation-2026-10-08.md):
   i file turzx_88inch_0015 presenti nel pacchetto sono MIPS/TUR_USB, non il
   chs_88inch ROM 1.90 seriale. Non usarli come prova e non caricarli sul device.

## Implicazioni per il prodotto

Si può realizzare un'attesa autonoma personalizzata sull'8,8 usando i media
della SD e il suo start mode. L'interfaccia deve dichiarare la selezione reale
del firmware (album/primo video), senza promettere un file arbitrario o la
sostituzione del logo iniziale. Il boot logo resta una capacità da indagare
se arriva un firmware/SDK seriale corrispondente o una cattura documentata.

Nessun nuovo test fisico dei modi di avvio in questo turno: utilizzate le prove
registrate, senza riavviare lo schermo, modificare file SD o impostazioni.
Strumenti Python di lettura metadati installati solo in target/fw-analysis-tools;
nessun eseguibile vendor o script del repository esterno avviato.
Prodotto e installazione invariati (.55 sviluppo, .45 installata).
